## A correction carried in this fold

The 0.30.109 fold said the trim room's entry pends a provisional "Package split" file. Reading the writer: that file belongs to the Marketplace's package splits (biz.ts, parent_item_id), not the trim room. Trim Packages Entry pends nothing when packages are entered; its containers are ledger rows beside the harvest package, and trim's only paper is a Package Adjustments row on the harvest package when the reconcile gate's "Queue an adjustment CSV" is chosen. The trim containers were never METRC packages, which is exactly the owner's model: the first true METRC package IDs after harvest are the ones cryo creates.

## The law, as built

1. THE RUN. A pasteurization schedule row IS the run: one production_schedules row per HBN (stage cryo, both item columns null). >> on the Pasteurization station makes the run and takes the HBN's free cryo-queue trim containers in as its inputs (cryo_run_inputs: the container, its type, its weight as it stood). A container trimmed later shows the HBN on Available again for another >> (his pick). A container is free while it waits in the Cryo Queue and no live run holds it; an unscheduled run frees its containers.
2. THE COLLAPSE. The Pasteurization station's three panes read the HBN and its pool, never a container: Available reads "n containers / X g in" on one line with the >>; Scheduled reads the run's pool in and out ("3 containers / 22,679.00 g in / 1 out, 22,000.00 g") with Pasteurizing, the < and the >; Complete reads the same with the completion time and no demote (a finished run has no step back). The rows scheduled per container under 0.30.97 fold into runs by migration 0058 (one run per HBN and status, the containers becoming its inputs, the per-container rows retired with the reason).
3. THE POOL. The run's inputs pool by product type (his word); the working pane shows Type, In (g), Out (g), Remaining (g) per type and the totals. THE OVERISSUE LINE IS STRICT: a line past a type's remaining, beyond half a cent, asks in words on the page and is never refused.
4. THE LINE. Cryo Weight Entry keeps its name and lists the scheduled runs by HBN in the left pane, no containers. The picked run shows the pool, the Effective Date (today by default, the Admin PIN for another day), the Operator (prefilled from the last line), and the trim-style line: scan the new package tag, pick the type from the pool's types, type the weight, press +. Each line is a new container (wip_packages source cryo, cryo_run_id the run): package_code the tag, weight and cryo weight its grams, cryo date the Effective Date, born straight into the Testing queue (his pick), with a ledger row at Cryo Room under the processor license AU-P-000694 beside the harvest package it draws on in METRC. The tag must be a true METRC tag (1A plus 22 hex; the line IS the METRC package), unused by any package or ledger row; the type must be in the pool; the weight above zero; the operator typed. The entered packages list beneath, newest first, with the reasoned pencil and void behind the PIN.
5. FINISH RUN. One control, armed once a package stands (with none it refuses: "Enter at least one package before finishing."): the trim containers the run took in move cryo_queue to pasteurized (transition cryo_consumed; archival, out of every queue and off the live inventory sheet) and their ledger grams go to zero under the reason "consumed by the cryo run; the container is archival"; the run completes. The Pasteurization station's > on a run is the same Finish run. A run with outputs cannot be unscheduled; a finished run cannot be demoted; the outputs' pencil and void carry any correction.
6. THE NEW PACKAGES FILE. A finished run with outputs pends "New Packages" on Pending Data Uploads as `new_packages_<HBN>.xlsx` in the owner's T3 autofill template byte for byte: its three header rows (the repeater row, the field paths, the labels) on the sheet named `new_packages_autofill_template.`, then one row per output: Tag Number the scanned tag, Location Name Cryo Room, Same Item yes, Quantity in Grams as a plain number, Actual Date the line's cryo date, and the ingredient Package Number the HBN's harvest package tag (the ledger row born at Finish lot, its tag or its code) with Ingredient Quantity the output's weight in Grams. An HBN with two lots draws from each lot's package in turn, a package's share being the grams its containers put into the run; an output that straddles two lots carries a second ingredient row with the line columns blank; an over issue folds into the last package. Finish Package and Ingredient Finish Date stay blank until his word. Mark uploaded and Clear all dispose it like every other file.
7. THE SHEET AND THE TAT. The Inventory sheet's live packages exclude pasteurized containers (their grams live on in the outputs); the Testing queue and its representative weight read the outputs. The TAT trim-to-cryo span for an output runs from the earliest trim container the run took in to the output's birth.

## Scribe assumptions (his word owed if wrong)

- The output tag must be a METRC tag shape; a non-tag line is refused, not kept and marked, because the line IS the METRC package.
- Outputs stand under the processor license AU-P-000694 at Cryo Room on the ledger (Cryo Room is not in the seeded location list; the file prints his word regardless).
- The New Packages ingredient is the HBN's harvest package tag (its internal code where no tag was typed), shares by lot in lot order; a second ingredient rides its own row with the line columns blank; the Actual Date prints as text YYYY-MM-DD.
- Finish Package stays blank on every ingredient row.
- A finished run has no demote; the Trimming station keeps its PIN-gated demote.
- The Marketplace's provisional Package split file and the trim reconcile gate's adjustment are untouched by this ruling.
