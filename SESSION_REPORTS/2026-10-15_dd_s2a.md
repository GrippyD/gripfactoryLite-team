## What landed

GET and POST `/admin/director/:dept/enter`, and GET `/admin/director/kpi/:key`, registered before the `/:dept` wall route and behind the Admin PIN. The grid defaults the cadence to the wall's first cadence and the period to the farm today, through the S1 period helpers. One row per KPI of that cadence. Hand and mixed rows are inputs (the total, and PNN, ARL, PNS when dims list farm). Other dimensions are named and not entered. App, mount, gc, and connector rows are locked, or they say "No snapshot yet". A posted locked cell is ignored. A blank with no hand row is skipped. A blank over a hand row supersedes it and does not insert. An equal value is skipped. A save that changes nothing does not write. A save that changes something is one write batch, one statement per row (supersede, insert, log), each under 100 binds. The person is the login through requireActor. The reason is required and defaults to "Weekly entry". The log field is value.

The detail page is one batch: the registry row, its question by config_key with the current app_config value, the value history for the last dd_history_periods periods, and up to 100 change-log rows for this key. An unknown key answers 404.

Each wall cadence that has a hand or mixed row links "Enter this period". Each tile title links to its detail. The home card says "N own KPIs".

## Shape of a POST

requireActor is the stations' direct read. The grid's own read is one batch. The write, when there is one, is a second batch. A no-op POST does not call the write batch. D1 prepares every statement in a batch before any of them run, so the read and the write cannot be the same batch.
