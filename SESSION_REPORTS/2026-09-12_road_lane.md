## The owner, verbatim

"I'm about to go on the road home for the weekend.  I'm going to be running this from my phone, but the terminal should stay up in the background.  Give me whatever permission requests you need to make commits and deployments"

## What the Scribe can and cannot reach

Commits already need nothing new: the repo folder is connected to the session and `device_commit_files` writes into it with the sha256 check both sides, as every slice today has. Deployments are the gap: the Scribe's sandbox is walled off from api.cloudflare.com (MEMORY, 2026-09-02), and the device bridge's shell is a Linux VM without wrangler's Windows login. The only place a deploy can run is the owner's own terminal, on the machine where wrangler is authorized. So the terminal becomes a lane: a watcher he starts before leaving, fed by files the Scribe commits.

## What shipped

**`app/scripts/deploy-watch.ps1`.** Every 20 seconds it writes `DEPLOY/heartbeat.txt` (so the Scribe can see it is alive) and looks for `DEPLOY/request.json`:

```
{ "id": "<uuid>", "mode": "fast" | "migrate", "canon": "0.30.x", "note": "..." }
```

For a request it has not handled it runs, from `app/`: `npx tsc --noEmit`, then `npm test`, then (mode migrate only) the D1 probe and `"y" | npx wrangler d1 migrations apply` with the database name read from `wrangler.toml` by the standing regex (THE NAME LAW FOR DEPLOYS), then `npm run deploy:grip`. A red step stops the chain; nothing deploys on red tests. The full output lands in `DEPLOY/log/<id>.txt`; the verdict (ok, the step that failed if any, every exit code, the version id read from wrangler's "Current Version ID" line, the machine, the times) in `DEPLOY/result.json` and `DEPLOY/results/<id>.json`; the request moves to `DEPLOY/done/<id>.json` so it never runs twice. A stale or unreadable request is set aside rather than blocking the lane. `DEPLOY/stop` (or Ctrl+C) ends it. Only env grip, only this repo, only the steps the standing block already runs.

**The Scribe's side.** A deploy becomes: commit the slice as always, then commit `DEPLOY/request.json`, wait, stage `DEPLOY/result.json` back, fold the version id into canon as always. The owner reads the fold on his phone.

**`.gitignore`** gains `DEPLOY/`. **`CLAUDE.md`** tells build sessions the lane exists and is the Scribe's alone.

**Start (his one command, from `app\`):**

```
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\deploy-watch.ps1
```

The machine must stay awake and the Claude desktop app running (the commits ride the desktop bridge). The lane is proven before he leaves with one fast-mode request that redeploys the current tree; its version id folds as the next LIVE record.

## Flags

The watcher is only as alive as his terminal, his machine's power settings and the desktop app; a dead heartbeat is the first thing the Scribe checks before writing a request. A migration-bearing request answers "y" to wrangler's apply prompt without a human at the keyboard; the Scribe writes `mode: migrate` only for a slice whose migration has passed the from-zero smoke, and never for the c10 environment.
