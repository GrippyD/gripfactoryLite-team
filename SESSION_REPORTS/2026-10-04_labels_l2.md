## The catalog

`src/labeldata.ts` names the fields a label can bind. Each has words in EN and ES, a type (text, number, date, or percent), and a resolver from a package tag. The resolver returns the value and the route that answered. The route is shown in the editor preview. It is not printed.

The fields: Package tag, Item, Category, Strain (the market strain where the app knows it, else METRC's item strain), Net weight and its unit, Packaged date, License, Facility name, Harvest name, Harvest date, HBN, HBN last five, THC percent, Test date, Lab, Lab test status, Production batch, Location.

They sit in four groups: Package, Harvest, Test, Company.

## Harvest date

The first route that answers wins:

1. The app's own harvest: `local_inventory_items` by the tag, then that harvest's `entry_date`. A voided inventory row still answers when no live row holds the tag. A live row wins when both exist.
2. A harvest named in the package's `source_harvests`, matched to `harvest_batches` by METRC harvest tag or HBN.
3. The date coded in that harvest name's first segment (two digits of year, three of the day of the year). Day 366 of a common year is refused. Day 366 of a leap year is 31 December.
4. The same three, walked up the lineage (`original_source_label`, then each of `source_packages`), at most six steps, never a loop.

Several harvests answer the earliest date, and the preview says so.

## THC percent

The newest passed compliance sample that carries a potency (`passed` or `retest_passed`, program compliance, not voided). A newer passed sample with no potency is passed over. Found by the package's own tag (`source_metrc_tag` or `sample_tag`), then the same lineage, then the package's harvest where exactly one passed potency exists for that HBN. Two differing potencies on a harvest answer blank. A failed sample is never taken. Internal readings are never read. None found: blank, route `no passed compliance potency`.

## Connections

The editor's Connections button, and Source Data on a text box, open one panel. Checkboxes for the four groups and every saved custom table. Checking a group or a table offers its fields. A click writes `{field}` into the selected text box, memo, barcode, or QR. Typed text can sit between fields (`Harvested {harvest_date}`). With no preview tag the editor shows the field's name. Preview with package shows that package's value, and the route list under the box. Print substitutes the values when a preview tag is set, and the field names otherwise. The route is never printed. No other D1 table is offered.

## Custom label data

`/compliance/labels/data` is the menu's third button. It lists saved tables (name, size, last saved), a pencil to edit, and an x that deletes with the Admin PIN (soft, and logged). The top of the form adds a table: name, Static or Keyed by Strain, Item, Category, or Harvest name, rows, columns, and a label and type on each column. Add the grid lays the cells. Save stores the table and returns to the labels menu. Start Over warns and clears. Exit Without Saving warns and leaves.

A static table's first row fills its fields on every label. A keyed table fills the row whose key cell equals the package's value. No matching row leaves the fields blank.

`label_data_tables` holds id, name, mode, key_field, columns_json, rows_json, and the audit columns. Every save and delete logs to `record_change_log`.
