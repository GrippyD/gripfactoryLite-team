Otherwise one db.batch: for each changed cell, UPDATE the old live hand row SET superseded_at = now (if any), INSERT the new dd_kpi_values row (id crypto.randomUUID(), source 'hand', entered_by the actor, reason, computed_at now, def_version from the registry row, created_at now; a blank cell against an existing hand row supersedes without inserting, which clears the value), and one record_change_log row (record_table dd_kpi_values, record_id the new row id or the superseded row id when clearing, field value, old_value the previous number or NULL, new_value the number or NULL, actor_person_id, reason, changed_at) through insertLog (src/db.ts:3745). Statements are per row (never a multi row INSERT above 100 binds); the batch carries them all. Redirect with ?ok=saved&n=<count>; the grid shows "Saved N values." Tests: a save of 120 cells with changes builds statements none of which binds more than 100 parameters (wrap the test db to record the bind count per prepared statement); one record_change_log row per changed cell and none for unchanged cells; a second identical save writes nothing (row counts equal before and after); a missing reason answers 400 "Reason is required."; a non numeric value answers 400 naming the KPI; a locked (app source) cell posted is ignored; a blank cell clears a hand value and logs it.
