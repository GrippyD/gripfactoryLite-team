## The law

1. THE FIELD CATALOG (`src/labeldata.ts`). One list of named fields a label can bind, each with its words (EN and ES), its type (text, number, date, percent) and its resolver from a package tag. At least: Package tag, Item, Category, Strain (the market strain where the app knows it, else METRC's item strain), Net weight and its unit, Packaged date, License, Facility name, Harvest name, Harvest date, HBN (and its last five), THC percent, Test date, Lab, Lab test status, Production batch, Location. Each resolver answers a value and the route it took (shown in the editor's preview, never printed).
2. HARVEST DATE, CLEVERLY. In order, the first that answers: (a) the app's own harvest for the package (`local_inventory_items` by `metrc_tag`, its `harvest_batch_id`, the harvest's `entry_date`); (b) the harvest named in the package's `source_harvests` matched to a `harvest_batches` row by its METRC harvest tag or name; (c) the date coded in that harvest name's first segment (two digits of year, three of day of year; refused if the day is not a real day of that year); (d) the same three walked up the package's lineage (`original_source_label`, then each of `source_packages`, at most six steps, never a loop). A package from several harvests shows the earliest date and says so in the preview route.
3. THC PERCENT, CLEVERLY. The newest passed compliance sample (passed or retest_passed, the station's set: program compliance, not voided) that carries a potency, found by: the package's own tag as `source_metrc_tag` or `sample_tag`; then its lineage as in 2 (d); then the package's harvest (its HBN as `harvest_batch`) where exactly one passed potency exists for that harvest. Never an internal reading. None found, blank, with the route "no passed compliance potency".
4. CONNECTIONS (the editor's button, and Source Data in a text box's options). A panel with checkboxes: the field catalog's groups (Package, Harvest, Test, Company) and every saved custom label data table. A text box, memo, barcode or QR may bind to one field (its content becomes `{field}` on the label, shown in the editor as the field's name or, when the editor's "Preview with package" box holds a tag, that package's value). Several fields may join in one text box with typed text between them (for instance `Harvested {harvest_date}`). Raw table access to any other D1 table is not offered (the catalog is the connection).
5. CUSTOM LABEL DATA (`/compliance/labels/data`, the menu's third button), as his words: the list of saved tables (name, size, last saved; pencil to edit, x to delete with the Admin PIN, soft and logged); the top line adds a new table; two fields set its rows and columns; each column gets a label and a type (text, number, date, percent); "+" lays the grid in the working pane to type into; Save (saves and returns to the menu), Start Over (warns and clears), Exit Without Saving (warns and leaves). A table is either Static (its first row fills its fields on every label) or Keyed by a catalog field (Strain, Item, Category or Harvest name): at print the row whose key cell equals the package's value fills them; no matching row leaves them blank. Migration 0093: `label_data_tables` (id, name, mode, key_field, columns_json, rows_json, the audit columns, soft delete); every write logged.
6. THE COVERAGE FIGURES, for the report: on the newest snapshot in the MAIN folder's `db_backups/`, over the mirror's live packages (`gone_at` null), how many resolve a Harvest date and a THC percent, by each route of 2 and 3, and how many resolve neither. The Scribe re-checks them at the gate.
7. WORDS: EN and ES for every field name, label, button and refusal.
