## The laws

2. THE RAD SCHEDULE, `/compliance/rad_schedule`, a tile "Rad Schedule" (ES "Programa del Rad") on the Compliance Console after Compliance Testing, its page in a new `src/rad.ts`, three panes (`station-triple`).
   LEFT, Available (ES "Disponibles"): the mirror's live packages (`gone_at IS NULL`, every mounted license) whose item type is BUD, WPR, SHA, PRE, MOB or WBP and whose `lab_test_status` is NotSubmitted, TestFailed or RetestFailed, and which stand on no open run (scheduled or running); a package whose lineage names no harvest the app can mint is not listed (the adopt pane's own rule, since completion adopts). Sorted by testing state (NotSubmitted, TestFailed, RetestFailed), then product type (BUD, WPR, SHA, PRE, MOB, WBP), then grow type as the HBN indicates (the batch's grow method through the lineage, else the HBN code's segment, Unknown last), then the tag's last five as a number ascending. Each row: the tag's last five (the full tag in its title), the type, the strain, the quantity with its unit (grams, or each with the gate's unit grams beside), the state, the grow type, and `>>`. The filter `?q=` (the tag's last five or the HBN, as the prepack scheduler filters) rides every post on this page. Each row carries `data-rad-tag`.
   MIDDLE, Scheduled (ES "Programados"): the runs in status scheduled, newest first, each a card (`data-rad-run`): its scheduled time in farm time, Grey (ES "Gy") as a select 100 to 3000 by 100 with Save (`setRadRunGrey`, logged, reason `rad grey set`), its packages in position order (the position, the tag's last five, the type, the strain, the quantity, `<` to take the package off the run: the row soft-deleted with reason `rad unscheduled`, the run itself voided with that reason when its last package leaves), and the count "n of 10". `>>` on an Available row (`scheduleRadPackage`) puts the package on THE OPEN RUN: the newest scheduled run with fewer than ten packages; when none, a new run is born with the grey of the newest run of any status (the last value; the first run ever at 100), logged (`logsForInsert`, reason `rad scheduled`); the eleventh package is refused in words ("That run is full; start a new run." / ES "Esa corrida esta llena; inicie una nueva."). A control "New run" (ES "Nueva corrida") at the top of the pane births an empty run deliberately (so the scheduler can build two side by side; the newest open one takes the next `>>`); an empty run that is not started by the end of the farm day is nothing to worry about, it stays scheduled and empty until used or voided by `<` on nothing (a "Remove run" control on an empty card, reason `rad unscheduled`).
   RIGHT, Done (ES "Listos"): the completed runs of today and the six farm days before, each with its grey, started and completed in farm time, its packages, and the words "ready for testing" (ES "listo para pruebas").

## Assumptions for his word

- The order: V9 after V8, before V7 unless his walk of CSA and CSB lands first; V10 after.
- The first run ever takes a grey of 100, the lowest step, until the scheduler picks; every later run takes the newest run's grey, his "default to the last value".
- `>>` fills the newest scheduled run with room; New run starts another; a run holds one to ten packages.
- One run in the Rad at a time; a second Start is refused while one runs.
- Completion's effect: an app row returns to the testing queue; a package the app never minted is adopted from the mirror as the prepack adopt does and enters the queue for the first time; a lineage with no harvest keeps a package off the pane.
- The Ready pane of the Testing gate counts a package as pasteurized once a run with it completes (the cryo outputs' rule extended); a TestFailed or RetestFailed package after the Rad waits on the Testing Desk's retest and is not in Ready until METRC says NotSubmitted again, V4's law unchanged; if he wants failed-and-radded packages in Ready, that is one line.
- Reopen behind the PIN returns a run to running and lifts its pasteurized mark; the package rows the effect moved stand where they are.
- The Done and Completed panes show today and the six farm days before, the rest in the record and the log.
- The grow type for the sort comes from the app's batch through the lineage, else the HBN code's segment, else Unknown last; the product types sort in the doc's order with the two riders after (BUD, WPR, SHA, PRE, MOB, WBP).
- The grey is a whole number of Gray from 100 to 3000 by 100; nothing is written to METRC by any act on these pages.
