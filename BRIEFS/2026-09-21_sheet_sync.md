## The law to build

1. THE SOURCE: Microsoft Graph with client credentials. Vars under `[env.grip.vars]` in `wrangler.toml`: `MS_TENANT_ID`, `MS_CLIENT_ID` (identifiers, not secrets; the build writes them as `"TBD"` and the owner fills them). The secret `MS_CLIENT_SECRET` is a wrangler secret (`npx wrangler secret put MS_CLIENT_SECRET --env grip`), never a var, never in any file. The drive id, item id and tab name are values in data (canon L-4), app_config `sheet_drive_id`, `sheet_item_id`, `sheet_labor_tab` (seeded by migration 0066 with the ids above and `Labor`), editable in Admin, Lookups, app_config. Token: `POST https://login.microsoftonline.com/{MS_TENANT_ID}/oauth2/v2.0/token` with `grant_type=client_credentials`, `client_id`, `client_secret`, `scope=https://graph.microsoft.com/.default`. Metadata first: `GET https://graph.microsoft.com/v1.0/drives/{drive}/items/{item}?select=id,name,cTag,eTag,lastModifiedDateTime,size,webUrl`; when the `cTag` equals the last successful run's, the run records `skipped` (unchanged) and downloads nothing. Otherwise `GET .../drives/{drive}/items/{item}/content` (Graph answers 302 to a pre-authenticated URL; `fetch` follows). The default env (wrangler dev, the smoke) carries no `MS_*` var; there the sync reads `SHEET_FIXTURE_URL` when that var is set and records `failed: no source configured` otherwise. A fixture URL is never read when `MS_TENANT_ID` is set: production reads Graph alone.
2. THE READER (no dependency; `src/xlsx.ts` today only writes): a zip reader for the workbook bytes: find the end-of-central-directory record (signature `0x06054b50`) from the tail, walk the central directory (`0x02014b50`) for the entries' names, methods, sizes and local header offsets, read each needed entry through its local header (`0x04034b50`, honoring its name and extra lengths), method 8 inflated through `new DecompressionStream("deflate-raw")`, method 0 taken as is. The workbook is 1.5 MB, 119 entries, all deflated; read only `xl/workbook.xml`, `xl/_rels/workbook.xml.rels`, `xl/sharedStrings.xml` and the Labor sheet part (`worksheets/sheet10.xml` today; resolve it by name every run: `<sheet name="Labor" r:id="rId10"/>` in workbook.xml, `rId10` to `worksheets/sheet10.xml` in the rels; a Target may be absolute `/xl/...` or relative to `xl/`). Parse the sheet XML with a tolerant regex or hand tokenizer (no DOMParser in Workers): header on row 3 (B DAY, C DATE, D HARV FARM, E HARV WET WEIGHT LBS, F TOTAL # OF PLANTS, G # OF TOTES, H CUT/BCK # PPL, I CUT/BCK # HRS, ... T TRIM INPUT LBS, V TRIM # HRS, ... AK FF LBS/PPL/HR; the header cells are shared strings, `t="s"`, index into sharedStrings `<si><t>`), data from row 4. Column C is a date serial in `<v>` (the 1900 system: `1899-12-30` plus the integer part, `date1904` absent), often behind an array formula `<f t="array">` whose cached `<v>` rules; column D is the farm, a formula string `t="str"` with the text in `<v>` (ARL, PNN, PNS; trim and uppercase; also accept `t="s"` and inline `t="inlineStr"`); column I is the hours, a plain number in `<v>` (a cell with no `<v>` is blank; `<f>` is ignored, the cached value rules). Assert the header reads `DATE`, `HARV FARM`, `CUT/BCK # HRS` in C, D, I before landing anything; a moved column fails the run in words.
3. THE LANDING: a row lands when it has a real date, a farm in ARL/PNN/PNS and a numeric hours cell; a row dated after the farm's today (canon 0.30.151, `farmToday`) is skipped and counted; blank hours or a blank farm skip (a blank never clears a console number). No cap on the number (his pick "Take it as typed": the September 14 PNN 2,753 and September 15 PNS 3,153 land as they stand). Upsert `harvest_labor_hours (farm_code, work_date)`: insert where missing (a change-log line, old NULL, new hours), update where the stored hours differ (old and new logged), nothing where equal; hours rounded to two decimals; `actor_person_id` NULL (a system run) and the reason `SYSTEM_REASON.sheet_sync` = `hours from the sheet (sync)`. The sheet is the source: a number typed on the console for a farm-day the sheet also carries is replaced at the next run; say so on the console line (law 6). Every write of one run in one `db.batch`.
4. THE RUN RECORD: migration `0066_sheet_sync.sql`: `sheet_sync_runs (id TEXT PRIMARY KEY, started_at TEXT NOT NULL, finished_at TEXT, status TEXT NOT NULL, trigger TEXT NOT NULL, workbook_modified_at TEXT, workbook_ctag TEXT, rows_seen INTEGER, rows_landed INTEGER, rows_changed INTEGER, rows_skipped INTEGER, message TEXT)` with an index on `started_at`; `status` in `ok`, `skipped`, `failed`; `trigger` in `cron`, `admin`; `rows_landed` counts inserts, `rows_changed` updates, `rows_skipped` the future, blank and non-farm rows; `message` the error text on `failed` (Graph status and body head, never a token). The same migration seeds the three app_config rows. Keep the last 500 runs (delete older at the end of a run).
5. THE CRON: `[env.grip.triggers] crons = ["15 * * * *"]` (a quarter past every hour, UTC; hourly is his pick); `src/index.ts` exports `{ fetch: app.fetch, scheduled }` where `scheduled(event, env, ctx)` does `ctx.waitUntil(runSheetSync(env, "cron"))`. The default and c10 envs carry no cron. THE SERVICE ACTOR (0.30.140) is untouched: the cron is not a request.
6. THE FACE: Admin gains a `[Sheet sync]` button (PIN-gated like the rest) to `/admin/sheet-sync`: the last ten runs (started, status, rows seen/landed/changed/skipped, message), the sheet's name and web URL from the last metadata, and a `Run now` form (`POST /admin/sheet-sync/run`, runs the sync with trigger `admin`, redirects back with `?ok=ran` and flashes the run's status in words). The Harvest Console's sheet hours line (`trimSheetHoursLine`, `data-hc-metric="trim_sheet_hours"`) gains a second line: `read from the sheet at <Eastern time> (<n> rows, <m> changed)` after an `ok` run, `sheet unchanged since <time>` after `skipped`, `sheet read failed at <time>: <message>` after `failed`, `sheet never read` before any run; say in the console footnote that the sheet is the source and replaces a typed number at the next hour.
7. STRINGS: everything shown translates through `src/i18n.ts` (EN, ES).
