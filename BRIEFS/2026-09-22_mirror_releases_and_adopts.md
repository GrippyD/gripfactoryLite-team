## The law to build

1. THE MIRROR RELEASES THE QUEUE. `mountMetrcExport` (`metrc.ts`) already closes the ledger for gone tags after a packages mount (`closeLedgerForGoneTags`, canon 0.30.128). Add its sibling, `releaseTestedFromMirror(db, actorId, mountId, ts)`, called right after it for a packages mount: every `wip_packages` row with `status = 'testing_queue'` (deleted_at NULL) whose tag matches a live mirror row (`metrc_packages.gone_at IS NULL`, matched on `UPPER(TRIM(p.package_code))` as 0.30.128 matches, and also through its ledger item's `metrc_tag` when the code is not the tag) with a `lab_test_status` in the release vocabulary is released: `status` to `released` through `nextStatus("released", status)` exactly as the hand release does, `test_outcome` to the vocabulary's word, two log rows (status, test_outcome) with the mount's actor and the reason `metrc mirror: <the METRC state> (mount <first eight of the mount id>)`. The vocabulary is data, app_config `metrc_release_states`, seeded `TestPassed=passed;RetestPassed=passed;TestFailed=failed;RetestFailed=failed` (a `state=outcome` list, the outcome one of TEST_OUTCOMES); a state not in the list (NotSubmitted, SubmittedForTesting, anything new) leaves the row in the queue. The mount's flash names the count in words: `N released from the Testing Queue by METRC (n passed, n failed)`, zero said as zero. Idempotent: a released row is not in the queue and is not touched twice. The same function runs from the Part 3 sweep (`metrcapi.ts`) at the end of a sweep that has written any mirror package's `lab_test_status`; if today's sweep writes no `metrc_packages` row, the call is a no-op and the report says so in one line, nothing invented. The hand Release keeps its place for a state the vocabulary does not carry.
2. THE QUEUE SHOWS THE MIRROR. The Testing Queue (`pipeline.ts`, key `testing_queue`) gains a column `Lab status (METRC)` read from the live mirror row by tag (`lab_test_status`, or `not in METRC` when no mirror row), so a hand release has the state in view and a row the mirror says has passed but still sits in the queue is visible as such (it should not exist after a mount; if it does, the reason is the vocabulary).
3. ADOPT FROM METRC. The Prepack scheduling page (`scheduling.ts`, stage prepack) gains a section under Available, `From METRC` (`data-schedule-adopt`): the live mirror packages (`gone_at IS NULL`) whose item kind (`metrcItemKind`, the Item name's first segment: `WPR - Wild Mango Creamsicle - PNN - O` reads WPR) maps to the WPR category through `cryo_type_categories` (the same rule the feed uses for a type code), `uom` grams, `quantity` above zero, `lab_test_status` mapping to `passed` in the vocabulary of law 1, and no app row (no `wip_packages` with `package_code` the tag, no live `local_inventory_items` with `metrc_tag` the tag). Each row reads the last six digits of the tag, the strain (`item_strain`, else the Item name's second segment), the grams (`roundGrams(quantity)`), the location and the license, and carries an HBN select prefilled by resolution: the mirror row's `source_harvests` matched against `harvest_batches.hbn`, else the `source_packages` looked up in the mirror and their `source_harvests` matched (two hops at most), else empty for the operator to pick; Adopt is refused in words while no HBN is picked. [Adopt] posts the tag and the HBN and mints, in one batch with its log rows under the reason `adopted from METRC`: a `wip_packages` row (`package_code` the tag, `package_type_code` the item kind, `wet_weight_entry_id` the HBN's lot as `lotByHbn` in `intesting.ts` picks it (the trimmed lot first), `weight_grams` and `cryo_weight_grams` the whole grams, `status` released, `test_outcome` passed, `source` `metrc`, a new `WIP_SOURCE`); a ledger item (`local_inventory_items`: `item_kind` WIP, `package_code` and `metrc_tag` the tag, `qty` the whole grams in g, `location` the mirror's location as the ledger names it, `license_value` the mirror's license, `harvest_batch_id` the HBN, `strain_id` by the strain name when a strain matches else null, `wip_package_id` the new row). The adopted package then stands in Available like a cryo output and schedules, packs and finishes like one; its Finish file and New Packages ingredient carry its tag. A tag adopted once leaves the From METRC list because it now has an app row.
4. THE FEED KNOWS BOTH SOURCES. `PREPACK_PARENT_SQL` takes `p.source IN ('cryo', 'metrc')`. Every clause that treats a non-cryo package as trim output is audited and excludes the adopted source too: `console.ts` (the trim picture's `p.source <> 'cryo'` clauses at the day's packages, the recorded grams and the created-since query), `feeds.ts` (`COALESCE(p.source, 'trim') <> 'cryo'`), `db.ts` (`CRYO_FREE_CONTAINER_SQL`), `actions.ts` (the two `existing.source !== WIP_SOURCE.cryo` branches on edit and void). An adopted package is never a trim container, never a cryo input, never in the trim picture; the test proves it for each clause.
5. THE WORDS. Spanish speaks on every new string (the column, the flash, the From METRC section, Adopt, the refusals).
6. NOTHING ELSE MOVES. The desk's `test_orders` and `test_samples` are not written by this brief; the release mirrors the hand release alone. Migration 0072 seeds `metrc_release_states` and nothing else changes shape.
