## 1. Targets on the KPI detail
The S2a detail page gains a targets block: the live dd_targets rows for the key ordered by effective_from, a void button per row (reason required), and an add form (dim_key from '' and the row's dims; period_kind; effective_from date; target; low; high; phasing; note; reason). The history table gains the target in force per period and the variance when both exist. Markers `data-dd-target`, `data-dd-target-form`.

- PHASING MEANS: blank, the target is per period as entered (a week target is that week's number). `flat` or weights, the target is an annual number phased to the row's kind: `flat` is target over 12 (month) or 52 (week); 12 weights only on a month row, 52 only on a week row; weights sum to 1 (within 0.001) or to 100 (within 0.1) and are stored normalized as comma separated shares summing to 1 in dd_targets.phasing. Phasing on a day, quarter or season target is refused.
- `POST /admin/director/kpi/:key/target`: target a number; low and high numbers or blank, low at most high; effective_from a date; period_kind as rule 0; dim_key from ddAllowedDimKeys; phasing as above. A second live row on the same (kpi_key, dim_key, period_kind, effective_from) is refused in words, not by the unique index's error. Write the dd_targets INSERT yourself and its log rows with `logsForInsert(db, 'dd_targets', id, record, actorId, reason, now)` (src/db.ts; it returns one log row per non blank field and inserts nothing itself), in one batch. Redirect `?ok=target`.
- `POST /admin/director/target/:id/void`: reason required; deleted_at and deleted_by set; one log row (field deleted_at). Redirect.
- Pure helpers in src/director.ts with tests: `parsePhasing` (blank, flat, 12, 52, percentages, a rejected list, 52 on a month row refused), `targetInForce` (the live row with the matching kpi_key, dim_key and period_kind and the latest effective_from on or before period_start), `phasedGoal` (blank phasing returns the target; otherwise the annual target times the share of the period: month index 1 to 12, ISO week 1 to 53 with W53 clamped to 52).
- The walls read the target in force for each tile's goal line where S1 left the goal blank (same batch; the S1 goal_ref and goal_direction rules stand). If that would need a second round trip on the wall, say so in the report and leave the wall as is.
- dd_phasing (the shared shape table) stays unused in S2b; phasing lives on the target row.

## 3. CSV import
`GET /admin/director/import`: two forms, Values and Targets, each a textarea for pasted CSV and a file input (multipart; read uploads the way src/imports.ts does), a reason, and Preview.

- `POST /admin/director/import/preview?kind=values|targets`: parse with `parseCsv` (src/csv.ts). Values columns: kpi_key, period_kind, period_start, dim_key (blank is the total), value (or value_text for a text unit), source_as_of (optional date). dd_kpi_values has no note column; a values CSV carrying a note column gets it refused in the preview with a plain message. Targets columns: kpi_key, dim_key, period_kind, effective_from, target, low, high, phasing, note. Validate every row: unknown key; a period_kind that does not match the row's cadence; a period_start that is not a period start for its kind; a bad number; a dash character; a dim_key not in ddAllowedDimKeys; a values row for a KPI that is not hand or mixed; a duplicate (kpi_key, period_kind, period_start, dim_key) inside a values CSV; a duplicate (kpi_key, dim_key, period_kind, effective_from) inside a targets CSV or one matching a live dd_targets row; more than 5,000 rows. The commit runs as several batches, so anything that would trip a unique index must be caught here, before the first write. Render a preview (row number, parsed cells, error text), the ok and error counts, and Commit only when there are no errors; Commit re-posts the same CSV text (hidden field) and the reason.
- `POST /admin/director/import/commit?kind=...`: requireActor, requireReason, re-validate (refuse with 400 if any row fails), then write in db.batch calls of at most 50 statements, one row per statement, as the grid does (supersede, insert, log); a values row equal to the live hand value is skipped. Targets through the same insert and logsForInsert as the detail form; count their log statements toward the 50. Redirect `?ok=imported&n=<rows>&skipped=<n>`.
