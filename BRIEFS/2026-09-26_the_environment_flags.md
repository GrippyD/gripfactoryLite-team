## The law to build

1. THE PULL. A second cron expression, every five minutes, beside the hourly one (the hourly jobs keep their minute; the handler tells the two apart by `event.cron`). When both secrets exist, `SENSORPUSH_EMAIL` and `SENSORPUSH_PASSWORD` (wrangler secrets only, never in the repo, a log, the change log, a page or canon), the pull authorizes, keeps the access token in D1 where no page, export or log reads it and renews it before its twelve hours, then asks `/samples` for the bound sensors since each one's newest stored reading, and stores the newest sample per sensor per poll in `sensor_readings` (the binding's space as `room`, `source` `sensorpush`, the observed time as `read_at`, plus the sensor id and its role), never the same (sensor, observed) twice. A refusal (a 429, a 401, the network) skips that poll, records one line where Admin can read it (the last pull's time, count and error), and waits for the next cron; it never retries in a loop. The base URL is a var (`SENSORPUSH_API_BASE`, default the public one) so the smoke points it at a fixture route, as the sheet sync does with `SHEET_FIXTURE_URL`.
2. THE BINDINGS. A new Admin page, Environment, behind the Admin PIN: the account's sensors as `/devices/sensors` lists them (name, id, battery, the newest reading stored), each with a space select (every live dry space and each cure room) and a role select (`room`, `bed`, `plenum`, `exhaust`), saved with its change log rows; an unbound sensor is never pulled. A button re-reads the list. These bindings are GripFactory Lite's own; Silo Ops' sensor map (its Setup, Silos screen) is never read or written.
3. THE RANGES. Per space and role, a low and a high temperature in F and a low and a high humidity in percent, each optional (blank is not checked), edited on the same page with reasons logged; the stale window in `app_config` (`environment_stale_minutes`, seeded 60).
4. THE FLAG. A bound sensor is OUT when its newest reading falls outside a set bound, STALE when its newest reading is older than the window or it has none since it was bound, IN otherwise. A flag names the role, the reading and the bound it broke (`Plenum 104.2 F, above 100 F`; `Room humidity 71 %, above 62 %`; `Bed no reading for 1 h 40 m`).
5. WHERE OPERATORS SEE IT. The silo strip's tile for the space, on every page the strip tops, carries its flags in the danger color, and the strip's refresh carries them (new fields in `/silos/live.json` beside the existing ones, which do not change, so Silo Ops keeps reading what it reads). The Drying line of the Operations map (brief P part two) reads a flagged space's flag after its clock. The cure panes' CONDITIONS line turns red when a room is OUT, as it does when stale. The freezer's tile flags like any other. On screen only: no message, mail or push.
6. THE FREEZER, EITHER WAY. A reading with a temperature and no humidity is valid on both paths, the pull's sample and the door's `POST /sensors/readings` (a freezer has no humidity to report; the migration makes humidity optional). The door's room list grows to every live dry space beside the cure rooms. The ranges and the flags read a space's newest reading from either source, so a bridge that posts the Blast Freezer's PLC temperature to the door (room: the freezer's name, the `sensor-bridge` token that already exists) is flagged exactly like a bound SensorPush sensor. The bridge itself, on a machine at the farm, is not in this brief.
7. NOTHING ELSE MOVES. `POST /sensors/readings` and its token stand; the cure panes' reading of `sensor_readings` stands (a room fed by the pull shows on its pane); the hourly jobs; every clock, load and unload law; Silo Ops.
8. THE TESTS. The pull against a stubbed SensorPush: the authorize and token calls, the token kept and renewed, the samples call's body, the newest sample stored once, a 429 skipping the poll with its line, no call at all without the secrets. The bindings and the ranges pages. The flag: in, out on each bound, stale by the window, never read. The strip's markup and the new `/silos/live.json` fields, with the old fields unchanged. `scripts/smoke.mjs`: bind a fixture sensor to Silo 3 as plenum, set a range, trigger the cron against the fixture route, see the flag on the strip and on live.json, then an in-range reading clearing it; a temperature-only reading posted to the door for the freezer, out of its range, flagged on the freezer's tile.
