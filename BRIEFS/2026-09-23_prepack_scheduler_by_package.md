## The ruling (owner, 2026-09-23, verbatim)

"I'm not sure the production scheduling surface for prepack makes sense to me.  If I adopt a package to an HBN does it conflate that package ID to the HBN I adopted?  Or is that a filter?  HBNs can't be changed, they live with every package and are inherited generationally.  A filter at the top of the list for HBN or last 6 would be useful, but the scheduler should only really be scheduling by the package ID (or the last six digits of it).  Use the ">>"/"<<" system we've precedented throughout the app."

The Scribe's answer to his question: today's Adopt writes the picked HBN onto the package (its `wip_packages` lot, its ledger item, its schedule row); it is a binding, not a filter, and it goes. His pick on the question tool for the strangers whose METRC harvest the app never minted (the ten from `46248-PNN-ID-062-1-NA-26002`, `46254-PNN-ID-005-1-NA-26004`, `46258-PNN-ID-062-0-NA-26007`, `46268-PNN-OD-078-0-NA-26009`): "Mint the HBN from METRC" (adoption creates the harvest batch in the app from METRC's harvest name exactly as METRC states it, marked as born from METRC, with no lot weighed here; the package inherits it; no pick anywhere; every stranger with a Source Harvest is adoptable).

## The law to build

1. THE PACKAGE CARRIES ITS HBN. `wip_packages` gains `harvest_batch_id` (migration 0073: a rebuild of the table that adds the column, makes `wet_weight_entry_id` nullable, keeps every other column and index as they stand, and backfills `harvest_batch_id` for every existing row from its lot's `harvest_batches` row; an index on `harvest_batch_id`). Every writer of a `wip_packages` row sets it (Trim Packages Entry from the lot, the cryo run from the run's HBN, the adoption from METRC's lineage). The prepack feed (`PREPACK_PARENT_SQL`), the scheduled and complete lists (`listPrepackScheduled`), the station's job (`loadJob`, `loadParentItem`), the pending files and the console's Prepack section read the HBN from `p.harvest_batch_id`, the lot LEFT JOINed and optional. The other stages keep reading their lots; nothing else changes shape.
2. THE SCHEDULER BY PACKAGE. The Prepack scheduling page (`scheduling.ts`, stage prepack) lists PACKAGES, not HBN groups, on all three panes: one row per package, `data-schedule-tag` the tag, `data-schedule-hbn` the HBN, the row reading the LAST SIX of the tag first, then the strain, the grams and the HBN muted. Available rows carry `>>` each (a form posting `wip_package_id` to `/production/scheduling/prepack/schedule` (PRODUCTION_SCHEDULING_PATH); the new action `schedulePackage` writes one `production_schedules` row for that package with its `harvest_batch_id` and the effective date, refusing in words a package that is no longer available or already scheduled); Scheduled rows carry `<<` (unschedule, today's action, still refused while lines stand) and the arrow `>` that opens the station (his accepted call); Complete rows read the last six and the time. `scheduleHbn` and the HBN grouping stay as they are for Trimming and Pasteurization (0.30.102, 0.30.110). The Available count is packages.
3. THE FILTER. A text box at the top of the Prepack page (`data-schedule-filter`, placeholder `HBN or last six`, label translated) narrows the rows of all three panes and of From METRC as the operator types (a small inline script matching the typed text, case-insensitive, against each row's `data-schedule-hbn` and the last six of `data-schedule-tag`; a pane with no match reads `- EMPTY -` in the muted style); the value rides `?q=` so a reload and a shared link keep it, and the server applies the same match when `q` is present so the page is right without the script. The filter never changes what is scheduled; it only narrows what is shown.
4. THE HBN IS INHERITED, NEVER PICKED. From METRC loses its HBN select. Each row reads the last six, the strain, the grams, the location, the license and THE HBN IT WILL INHERIT: METRC's Source Harvest of the package, else the Source Harvest of one source package in the mirror (the hop of 0.30.193), shown as the name with `known` when the app has that HBN and `new from METRC` when it does not; a row whose lineage names no harvest reads `no harvest in METRC's lineage` and has no Adopt. Adopt posts the tag alone. When the HBN is known, the package inherits it as today (`harvest_batch_id` and the ledger item's `harvest_batch_id`; no lot when the HBN has none, the trimmed lot when it has one, as `lotByHbn` picks). When the HBN is new, Adopt MINTS THE HARVEST BATCH from METRC's name in the same batch: `hbn` the name exactly as METRC states it (trimmed, upper case as the app stores HBNs); the seven segments read through `parseHbn` (0.30.141): `farm_code` the second, `grow_method_code` the third, `manicure` the fifth, `lot_serial` the last five digits of the seventh with `harvest_year` its first two (26007 is year 26, serial 7), `entry_date` the first segment's day when `dateFromYyddd` reads it and else the mirror's `packaged_date` and else the adoption's farm day, `planned_dryspc` the sixth segment (NA as the blank silo), `strain_id` the strain whose name matches the item's strain case-insensitively, else a strain minted from that name with `hbn_code` the fourth segment; `license_value` the mirror row's license; `status` the mint's first status; `born_from` `metrc` (a new column on `harvest_batches`, 0073, `TEXT NOT NULL DEFAULT 'app'`); log rows under `adopted from METRC`. A name that is not seven segments, or whose (harvest_year, lot_serial) already belongs to a different HBN, refuses adoption in words naming the harvest and the reason; nothing is minted on a refusal. A METRC-born harvest batch has no lot, no plants and no wet weight in the app: it exists to carry lineage.
5. THE METRC-BORN HBN STAYS OUT OF THE HARVEST. Every surface that lists or counts harvest batches as the farm's harvest excludes `born_from = 'metrc'` or is proven unaffected because it joins lots, plant tags or wet weights the METRC-born row never has: the HBN pencil and the mint pages, the Harvest Console's lots and plants and the by-strain-then-farm groups, the strain actuals, the dry space planning, the trim and cryo feeds, the Compliance Console's lot lists, the METRC uploads by HBN (the adopted package's own Finish and New Packages files pend under its HBN as any prepack job's do). The report lists each query touched or proven, one line each.
6. THE WORDS. Spanish speaks on every new string (the filter's label and placeholder, `known`, `new from METRC`, `no harvest in METRC's lineage`, the refusals, the empty line).
7. NOTHING ELSE MOVES. The mirror release (0.30.193) is untouched. The Trimming and Pasteurization pages keep their HBN groups and their `>>` per HBN. The station's line form, Finish Pack, the carry and the console's Prepack section are untouched beyond reading the HBN from the package.
