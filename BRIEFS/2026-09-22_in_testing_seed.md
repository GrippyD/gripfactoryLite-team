## The law to build

1. THE APP READS .XLSB. `src/xlsb.ts`: a reader for the MS-XLSB binary workbook, enough for a flat table: the package is a zip (the app already unzips xlsx for the Labor tab); `xl/workbook.bin` (BrtBundleSh: sheet name and relationship id), `xl/_rels/workbook.bin.rels` (the sheet parts), `xl/sharedStrings.bin` (BrtSSTItem), `xl/worksheets/sheetN.bin` (BrtRowHdr, BrtCellBlank, BrtCellRk, BrtCellError, BrtCellBool, BrtCellReal, BrtCellSt, BrtCellIsst, BrtFmlaString, BrtFmlaNum, BrtFmlaBool, BrtFmlaError). Record type and length are the variable-length encodings of the spec; RK numbers decode with their two flag bits; formula cells yield their cached value (the cached value rules, as the Labor tab). Dates are 1900-system serials and become ISO dates in the farm zone; a text date is parsed as the manual form parses it. Only the tabs and columns the table needs are read; the rest of the workbook is skipped. No new dependency: the reader is our own, like the xlsx reader.
2. TESTS WITHOUT THE REAL FILE IN THE REPO. The real workbook carries the Driver Info tab (names, phones: personnel, G-9), so it is never committed, never a fixture, never staged from chat. The owner drops a copy into `DROPS/In Testing (2026).xlsb` (DROPS/ is gitignored); the smoke and a local check read it from there when present and skip in words when absent. The unit tests build their own small .xlsb with a test-side writer (the inverse of the reader: a zip with workbook.bin, the rels, sharedStrings.bin and one sheet.bin of a few rows with every cell kind the reader handles), so the reader is proven on every run.
3. ONE PARSER, TWO DOORS. `src/intesting.ts` turns the two tabs into row records (one type per sheet row, the 18 named fields plus the tab and the row number) and lands them (law 4 and 5). Door one, the Admin upload: Admin, Imports accepts `.xlsb` (`IMPORT_KINDS` gains `xlsb`); an upload of this workbook runs the same landing as the cron and reads back the counts in words. Door two, the hourly cron: the existing scheduled handler runs the Labor sheet, the Metrc sweep and this pull; the pull reads the item by the two app_config ids through the same Graph client credentials (`MS_TENANT_ID`, `MS_CLIENT_ID` vars, `MS_CLIENT_SECRET` secret; never in a file); with them absent it records a skipped run, as the Labor sheet does; on the default env the fixture URL lane applies as it does for the Labor tab (a `.xlsb` fixture served by the smoke). Each run is a row in `sheet_sync_runs` with a new `source` column (`labor` or `in_testing`; 0070 adds it, the old rows read `labor`); Admin [Sheet sync] shows the last run of each source.
4. THE COMPLIANCE CONSOLE FOLLOWS THE SHEET. Each sheet row lands in `external_test_results` one for one: license_number, med_au, strain, item_name, source_metrc_tag, batch_weight_grams, hbn, sample_tag, required_test, net_weight_grams, testing_facility, entered_testing, finished_testing, potency_result (THC Potency %, the percent sign stripped), status (Testing Status as typed), failure_mode (Fail Reason as typed), and attempt (law 6). Provenance: 0070 adds `source` (`sheet` or `manual`, the old rows `manual`), `sheet_key` (tab, then the Sample Tag; when the Sample Tag is blank, the tab and the row number), `sheet_seen_at` (the run that last saw the row), `on_sheet` (1 while the last run saw it, 0 once a run did not). The upsert key is `sheet_key`. THE SHEET WINS on the columns above for rows whose source is `sheet`; a manual row (typed in /compliance, source `manual`) is never touched; a sheet row a later run does not find is not voided, it reads `on_sheet = 0` and the console shows it as no longer on the sheet. Every change of a stored value is a `record_change_log` row with no actor and the reason `in testing sheet` (a new `SYSTEM_REASON`); a row landing for the first time logs its creation as the imports do. The KPIs (Lbs in testing, the FTQ rate, the failure Pareto) read the table as they do today and so follow the sheet.
5. THE DESK'S HISTORY FOLLOWS THE SHEET. From the same rows, the desk's tables gain the season: one `test_orders` row per sheet row (panel from Required Test: Full Compliance is `full_compliance`, Potency is `potency`, the R&D tab and a Required Test naming R and D is `rnd`, anything else lands in `external_test_results` only and is counted as skipped in words; `source_package_tag` the Source Metrc Tag; `item_name`, `license_value`, `market` from Med/AU; `lab_id` by the lab alias table of law 7; `batch_grams` the Batch Weight; `sample_grams` the Net Weight; `status` from the Testing Status: `passed`, `failed`, else `sent` with no result; `created_at` the Entered Testing date, so the 0.30.178 order of a parent's history holds; `pickup_date` the Entered Testing date), one `test_samples` row (sample_tag the Sample Tag, net_grams the Net Weight, sampled_at the Entered Testing, attempt of law 6, overall_passed 1 for a passed status, 0 for a failed one, null otherwise, thc_total_pct the THC Potency %, results_at the Finished testing), and for a failed row one `test_results` row per Fail Reason part (split on commas; `passed` 0; the type map of law 7; `result_date` the Finished testing), plus for a passed row one `test_results` row of type `other`, passed 1, so the sample carries a result. The lot: `test_orders.lot_id` is resolved through the Harvest Batch Name to the HBN's finished lot when the app knows the HBN; when it does not (the season's early rows predate the app), 0070 relaxes `lot_id` to nullable (a table rebuild in the migration, Postgres-portable) and the order stands without a lot; the desk's lot-bound panes (lots ready, lots scheduled, retest waiting) skip an order without a lot, while the rate, the by-lab and by-strain groups (strain from the row's Strain, farm from the HBN's farm code segment) and the COA and THC lists read every order. Provenance on `test_orders` and `test_samples`: `source` (`sheet` or `desk`, old rows `desk`) and `sheet_key`; the upsert key is `sheet_key`; the sheet wins on its columns for its own rows; desk-made rows are never touched; a sheet row no longer found reads `on_sheet = 0` and stays in the rate.
6. THE ATTEMPT. For a row, the attempt is one plus the count of earlier rows on the same Source Metrc Tag and panel (earlier by Entered Testing, then by row order), the same rule the desk uses for a retest; a row without a Source Metrc Tag is attempt 1 on its own Sample Tag. `external_test_results.attempt` and `test_samples.attempt` carry the same number.
7. THE VOCABULARIES ARE DATA. Two app_config lists seeded by 0070 and editable in Admin, Lookups, app_config: `in_testing_lab_aliases` (`ACTLab=act-laboratories; ACT Laboratories=act-laboratories; ACT=act-laboratories; SC Labs=sc-labs-michigan; SC Labs Michigan=sc-labs-michigan; SCLabs=sc-labs-michigan; Lab Link=lab-link; LabLink=lab-link; Viridis=viridis`), matched case-insensitively after trimming; an unmatched Testing Facility keeps the row in `external_test_results` (testing_facility as typed) and skips the desk order in words, never inventing a lab. `in_testing_fail_types` (`Coliforms=microbials; Total Yeast & Mold=microbials; Total Yeast and Mold=microbials; Yeast & Mold=microbials; Heavy Metals=heavy_metals; Foreign Matter=foreign_matter; Water Activity=water_activity; Pesticides=chemical_residue; Chemical Residue=chemical_residue; Mycotoxins=mycotoxins; Potency=potency`); an unmatched part lands as type `other` with the part in `notes`. The status words: `Passed`, `Pass`, `Passed - Retest`, `Remediated` read passed; `Failed`, `Fail` read failed; anything else (blank, `In Testing`, `Pending`, `Sent`) reads no result yet. The THC: a number, a percent sign stripped, blank to null; `Turnaround Time (Days)` and `Notes` are not stored beyond `external_test_results` (Notes lands in a new `notes` column there, 0070).
8. THE RUN IN WORDS. A run reads the workbook once, lands both tabs, and records rows seen, rows landed, rows changed, rows skipped (with the first few reasons in the message: an unknown lab, an unknown Required Test, a blank Sample Tag) in `sheet_sync_runs` with `source = 'in_testing'`. The Admin upload answers the same counts on the page. A run that cannot read the workbook (Graph refused, not an .xlsb, a missing header) is a failed run in words and changes nothing.
9. WHOLE GRAMS. Batch Weight and Net Weight land as whole grams, rounded half up (the 448 law); the THC keeps its decimals.
