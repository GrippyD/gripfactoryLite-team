## The laws

1. THE REPORT. Key `line_packages`, title "Line packages", the card's blurb "Every package a line put out on a day: Trim, Prepack, Cryo/Rad; the day read from its start time." in `REPORT_KEYS` and `REPORT_CARDS`.
2. THE FILTERS (`reportFilterForm`): Line, a select with All, Trim, Prepack, Cryo/Rad (values `all`, `trim`, `prepack`, `cryo_rad`; default All); Date, `<input type="date" name="date">` defaulting to the farm's today (filled in the route as the labor hours window is); Date start, `<input type="time" name="start" step="60">` defaulting to the Admin farm day start hour as "HH:00" (the help under it: "The day runs from this time to the same time next day, Eastern. The default is Admin's farm day start hour."); Operator, a text box, case-blind contains on the row's operator; a bad `start` (not HH:MM) falls back to the default and the page says so in the footnote.
3. THE WINDOW (his pick). `[farmInstant-like start, end)`: `startIso = etInstant(date, start)`, `endIso = etInstant(dayAfter(date), start)`; a row is in the day when its instant is at or after `startIso` and before `endIso`. The instant per line: Trim and Cryo the package's `created_at`; Prepack the line's `created_at`; Rad the run's `started_at` (a run not started is not on the report). The typed Effective Date (`trim_date`, `cryo_date`, `work_date`, the Rad run's farm day of `started_at`) is a column, never a filter.
4. THE COLUMNS, in order: Line ("Trim", "Prepack", "Cryo", "Rad"; the group column, `groupBy: "line"`), Entered (`etWallClock(instant)`, the Eastern wall clock), Lot (the lot's short id for Trim as the station shows it, the parent package's HBN for Prepack, the run's HBN through the lineage for Cryo and Rad, blank when none), Package tag (Trim and Cryo `package_code`; Prepack `tag`; Rad `tag`), Type (Trim and Cryo `package_type_code`; Prepack "{unit} g x {bags}" from `unit_grams` and `bags`; Rad `item_type` with the grey after it, "WPR, 1500 Gy"), Weight (g) (`grams: true`), Weight (lb) (the same value, `lbs: true`), Effective date, Operator (Trim `trim_operator`, Cryo `cryo_operator`, Prepack and Rad the `people.display_name` of `created_by` / `started_by`, blank when the person is gone). Rows sorted by line in the order Trim, Prepack, Cryo, Rad, then by Entered ascending. Cryo/Rad as one filter value shows two groups.
5. THE TOTALS. ## Assumptions for his word

- "Line" is the three he named: Trim (Trim Packages Entry's packages), Prepack (the prepack lines, bags and grams), Cryo/Rad (the cryo outputs and the Rad runs' packages); the Rad rides with Cryo under one filter value and shows as its own group.

- Prepack and Rad have no typed operator; the person who did the entry (the Access identity) stands as the operator.
- Totals are per line shown, with the Trim line's types and bud percentage by the console's own law; the report does not restate the console's shift cards.
- The report is a new key on the existing Reports page with the existing CSV, XLSX and PDF; nothing else on the page moves.
