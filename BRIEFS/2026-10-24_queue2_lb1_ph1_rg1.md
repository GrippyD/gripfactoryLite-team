## THE RUNNER LAW (so the session does not stall)
- A command expected to run longer than three minutes runs in the background, with its output in a log. The from zero smoke takes five to eight minutes. Cursor ends a terminal call after about ten minutes, and a waiting foreground call is what stalls a session. Poll the log with short commands. From `app\` in PowerShell:

      $log = Join-Path $env:TEMP "gf-smoke.log"
      Remove-Item $log -ErrorAction SilentlyContinue
      Start-Process -FilePath "cmd.exe" -ArgumentList "/c node scripts\smoke.mjs > $log 2>&1 && echo SMOKE_EXIT 0 >> $log || echo SMOKE_EXIT 1 >> $log" -WorkingDirectory (Get-Location) -WindowStyle Hidden

  then, every 60 to 90 seconds until a SMOKE_EXIT line shows:

      Start-Sleep -Seconds 75; Select-String -Path $log -Pattern "About to apply|SMOKE PASS|SMOKE FAIL|SMOKE_EXIT" | Select-Object -Last 4

  SMOKE_EXIT 0 with SMOKE PASS is the pass. Put the About to apply line, the SMOKE PASS line and the SMOKE_EXIT line in the report. A tool call that times out while the smoke runs is not a failure: read the log.
- The smoke's line packages check reads the wall clock: a run that straddles 23:00 or 06:00 Eastern can fail it. If that check alone fails, rerun the smoke once clear of the hour and say so in the report.
- Never start a server or any other command that does not return in the foreground. The smoke runs its own worker.
- Nothing interactive: no logins, no prompts, no `npm init`, no editor.
- No browser and no screenshots (THE RENDER LAW, canon 0.30.535). Where a brief asks for a page check, assert it in tests or in the smoke. The Scribe renders every page at the gate.
- No git, no deploy, no wrangler command against the remote database.
- Do not stop to ask. When the brief leaves a choice open, take the reading closest to the brief and the app's existing laws, write it under "Decided" in the slice's report, and continue.
- Stop the queue only when a slice's starting tree is not the one this queue names, or when a gate stays red after two honest fixes. Then write that slice's report as it stands (what passed, what is red, the tree you are on) and stop; the slices after it wait.
