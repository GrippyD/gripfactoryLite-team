## The law to build

1. THE UNIT IS THE PARENT PACKAGE. The thing that passes or fails testing is the parent package, the batch the sample represents, named by its parent tag (`test_orders.source_package_tag` when tag-shaped, else `source_package_code`, else the lot id as a last resort). Every full compliance order on the same parent package is one testing history, in `created_at` order. The sample tag is a manifest detail and never a key in the Testing section.
2. THE FIRST FULL PANEL. A parent package enters the rate the moment its first full compliance panel has a result: the earliest order with `panel = 'full_compliance'` on that parent whose sample carries `overall_passed` (0 or 1). Passed means the package needed one panel. Failed means it did not, from that moment on, whatever a retest or a remediation does later. Orders with `panel` `potency` or `rnd` are never a panel for this rate, and a parent whose first full panel has no result yet is not in the rate at all.
3. THE WEIGHT. Each parent package weighs what its first full compliance order recorded as `batch_grams` (the dry grams of the batch when that panel was scheduled). The rate is the sum of the weights of the packages that needed one panel over the sum of the weights of every package in the rate.
4. THE FIGURE. The percent to one decimal, and under it two lines: the weights in pounds at 448 g to two decimals (`12,340.00 of 14,800.00 lb`), and the package counts (`9 of 11 packages`), so a person can still read the count the old way. An empty season reads `no results`.
5. BY LAB, THEN FAILURE TYPE. Group the parent packages by the lab of their first full panel; the same weighted rate per lab. Under each lab, the failure types: for the packages whose first panel failed, each failed `test_results.test_type` on that panel, with the weight (pounds) and the count of packages, a package failing two types appearing under both. Sort failure types by weight, largest first.
6. BY STRAIN, THEN FARM. Group the parent packages by the HBN's strain; the same weighted rate; under each strain, by the HBN's farm.
7. THE LISTS. COAs by parent tag and THC by parent tag stay keyed on the parent tag as Part 2 built them; each row gains the attempt number beside the date (`attempt 2`) so a retest row reads as one; the sample tag is never shown here.
8. THE FIFTY POUNDS IS NOT A GATE. Grip adds a few grams to every parent package for the sample itself, so a package is never exactly 50 lb and 50.3 lb is typical. The desk's refusal of a batch over 22,400 g comes out: `batchOverLimit` and the refusal string (`This batch is over 50 lb (22,400 g). R 420.304 limits a harvest batch to 50 lb.`, EN and ES) go, the Schedule action never refuses on weight, and the row simply shows the batch weight as it does now. The sample size stays 0.5 percent of the batch with the 14 g floor and the lab increment. The rate covers every parent package with a full-panel result whatever its weight. Canon 0.30.179 keeps the fact for later: the 50 lb figure is guidance for representative samples of non-infused product, infused product has no batch limit, and neither is a gate on this desk.
