## The laws

1. MIGRATION `0084_terp_recipes.sql`: `terp_recipes (id TEXT PRIMARY KEY, name TEXT NOT NULL, status TEXT NOT NULL, retired_at TEXT, retired_by TEXT, retire_reason TEXT, created_at TEXT NOT NULL, created_by TEXT, updated_at TEXT NOT NULL, updated_by TEXT, deleted_at TEXT, deleted_by TEXT, delete_reason TEXT)`, `status` one of `active`, `retired`; `terp_recipe_lines (id TEXT PRIMARY KEY, recipe_id TEXT NOT NULL, position INTEGER NOT NULL, terp_name TEXT NOT NULL, percent INTEGER NOT NULL, created_at TEXT NOT NULL, created_by TEXT)`; indexes `terp_recipes_status (status)` and `terp_recipe_lines_recipe (recipe_id)`; `ALTER TABLE production_schedules ADD COLUMN terp_recipe_id TEXT`; `ALTER TABLE production_schedules ADD COLUMN terp_dose_pct REAL`; an index `production_schedules_terp_recipe (terp_recipe_id)`. Null on every existing row. Postgres-portable SQL.
2. THE LOOKUP, "Terp Recipes" (ES "Recetas de terpenos") at `/admin/lookups/terp_recipes`, a tile in the Production Operations category beside Trim Bogey (its description and field help name as the other tiles carry), its page in a new `src/terps.ts`. THE BUILDER, top to bottom as the doc draws it: "Recipe Name" (ES "Nombre de la receta"), a text box; the working pane: "Terp Name" (ES "Nombre del terpeno"), a text box, beside it the percent box (a whole number, `inputmode="numeric"`, its default 100 with no line below, else 100 minus the sum of the lines below), "+" and [Start Over] (ES "Empezar de nuevo"); under it the pane of lines added, each "name percent%" with a minus sign that removes it, and the running total. "+" with an empty name or an empty percent shows the warning "Type a terp name and a percent." (ES "Escriba un nombre de terpeno y un porcentaje.") and adds nothing; a percent that would carry the total past 100 shows "That percent would pass 100." (ES "Ese porcentaje pasaria de 100.") and adds nothing. When the total reaches exactly 100 the prompt "This Mix is complete, would you like to save?" (ES "Esta mezcla esta completa, desea guardarla?") appears with [Save] (ES "Guardar") and [Start Over]: Save posts the recipe; Start Over clears the name and the lines and returns to the empty builder. The builder is the page's script: the lines live in the page as hidden inputs (`terp_name` and `percent`, repeated in position order) and post once on Save to `/admin/lookups/terp_recipes` with `action=save`; without script the same form stands as eight blank line rows under the name and a Save button, and the server is the judge either way.
3. THE SERVER ON SAVE (`saveTerpRecipe`): the name required, trimmed, unique among active recipes ignoring case ("That name is already an active recipe." / ES "Ese nombre ya es una receta activa."); at least one line; each line a non-empty trimmed name of at most 60 characters and a whole percent from 1 to 100; the percents summing to exactly 100 ("The percents must total 100." / ES "Los porcentajes deben sumar 100."); else refused in words with nothing written. On a good save, one batch: the recipe active and its lines in position order, logged (`logsForInsert` on the recipe and on each line, reason `create`); the flash "Recipe saved." (ES "Receta guardada."); the page reloads with the builder empty and the list below.
4. THE LIST under the builder: the active recipes newest first, each with its name, its lines "name percent%" in position order, the date saved in farm time, and [Retire] (ES "Retirar") with a reason box inline (required, the house's void pattern); under them the retired recipes, read-only, each with its retire date and reason, behind a "Show retired" toggle (ES "Mostrar retiradas") open when the page is asked with `?retired=1`. RETIRE posts `action=retire` with the recipe id and the reason (`retireTerpRecipe`): status `retired`, `retired_at`, `retired_by`, `retire_reason`, logged with the reason; refused without a reason. A retired recipe keeps its lines forever and stays on every run that picked it; it leaves the schedule's select and the default. There is no edit path: a recipe never changes after Save (his "This process should be uncomfortable"); a name may be reused by a new recipe once the old one is retired, the runs keeping the recipe they picked by id.
5. THE PICK ON THE SCHEDULE. On `/production/scheduling/cryo` each run in the Working pane carries, under its identity line, "Terp recipe" (ES "Receta de terpenos"), a select of the active recipes with a blank option "No recipe" (ES "Sin receta"), and "Dose" (ES "Dosis"), a number box (a percent of the lot's weight, two decimals, blank allowed), with a Save control; the post `/production/scheduling/cryo/terp/<runId>` (`pickTerpRecipe`) writes `terp_recipe_id` and `terp_dose_pct` on the run's row, logged as field changes (reasons `terp recipe picked`, `terp dose set`; a clear logged the same way), refused on a completed run ("Unfinish the run first to change its recipe." / ES "Reabra la corrida primero para cambiar su receta.") and refused for a retired or unknown recipe id. A completed run shows its recipe's name and its dose read-only on the Complete pane's row; a run with none reads "No recipe".
6. THE DEFAULT, his "like market strains": at `>>` the new run takes the recipe of the newest run (by `scheduled_at`, any status, not deleted) whose HBN's market strain equals this HBN's (`COALESCE(NULLIF(trim(market_strain), ''), the strain's name)`, compared trimmed and ignoring case) and whose recipe is still active; else none. The default is written on the run's row at `>>` in the schedule's own batch (a real pick, logged with the insert, changeable while the run is scheduled), so it stands whether or not anyone opens the page. The dose never carries (his "lot-by-lot decision"): blank on every new run.
7. THE RUN ON CRYO WEIGHT ENTRY: the picked run's header (`src/cryo.ts`) shows "Terp recipe: <name> (<line, line, ...>)" and "Dose: <n.nn> %" or "No recipe", read-only; the pick stays on the schedule page.
8. THE WORDS, EN and ES, ASCII: those above and the flashes "Recipe retired." (ES "Receta retirada."), "Terp recipe saved." (ES "Receta de terpenos guardada.").
9. NOTHING ELSE MOVES. The run's inputs and outputs, the queues, Finish run, the Complete and Unfinish acts, the console (V10 reads the run's recipe on the Right now pane later) and the reports untouched. `scripts/smoke.mjs` moves its pin to 84 and walks: the lookup (a recipe of three lines summing to 100 saved and listed; a save at 90 refused; a duplicate active name refused; a second recipe saved; the first retired with a reason, listed under retired); the schedule (a run for an HBN takes no recipe when none was picked before; the pick with a dose written and read back; a second HBN with the same market strain takes that recipe by default at `>>` and no dose; the recipe retired, off the select, and a later `>>` for the strain takes none; a completed run refuses a pick); Cryo Weight Entry showing the recipe on the run.

## Assumptions for his word

- The order: V8 after V15 and V15.1 are merged, before V7 unless his walk of CSA and CSB lands first.
- The dose is a percent of the lot's weight to two decimals; if the crew doses in mL per pound, the unit word changes and nothing else.
- The default recipe is written on the run at `>>`, read from the newest run of the same market strain, active recipes only; the dose never carries.
- The recipe and the dose change only while the run is scheduled; a completed run's pick stands until Unfinish behind the PIN.
- The percents are whole numbers, one to one hundred (the doc's "input mask to whole number %"); a terp name is free text up to 60 characters, the consumable list his later note.
- A retired recipe's name may be reused by a new recipe; the runs keep the recipe they picked by id.
- Retire asks a reason, the house's void pattern; no recipe is ever edited or deleted.
- The builder's script holds the lines until Save; without script the plain rows; the server judges both.
- The Cryo Weight Entry header shows the run's recipe and dose read-only.
