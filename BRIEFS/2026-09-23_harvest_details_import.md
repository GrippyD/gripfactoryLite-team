## The law to build

1. THE TWO BOOKS OF RECORD. The Harvest 2026 directory (the ops dash) is the book of record for REALITY: the harvest's date, farm, grow method, strain, market strain, manicure, tag, plants, cuts and weights come from it. METRC is the book of record for COMPLIANCE: the HBN string the app carries is METRC's harvest name whenever METRC has one for that lot. gripfactory reads real life and feeds the METRC pipeline. Where the two disagree, the HBN string follows METRC and every other fact follows the sheet, each change logged with its reason; the app never picks one book over the other by silence.
2. THE HARVEST DETAILS TAB RIDES THE SHEET SYNC. `runSheetSync` reads a second tab from the same workbook bytes, named by `app_config.sheet_harvest_tab` (seeded `Harvest Details` in 0074). Columns are found by the header text of row 4 (trimmed, case-insensitive, the newline inside `Wet Spear Weight\n(grams)` read as a space), never by letter; a header the tab lacks leaves that column null and is named once in the run's message. Data rows run from row 7 to the last row with a seven-segment `Harvest Batch Name` that `parseHbn` reads; a row with a blank or unreadable name is skipped and counted. The cached value of every cell is what is read (the same rule as the Labor tab); an Excel date serial in `Date` and `Seq. Date` becomes an ISO day; a text or error cell in a numeric column lands null. Every parsed row lands in `harvest_sheet_rows` (0074): `sheet_hbn` (the name as the sheet writes it, upper), `metrc_harvest_tag`, `row_no`, `sheet_date`, `farm_code`, `grow_method`, `strain_name`, `market_strain`, `manicure` (1, 0 or null), `cuts`, `plants`, `wet_spear_g`, `bucked_wet_g`, `seq`, `seq_date`, `silo`, `dry_weight_g`, `dry_down`, `moisture`, `water_activity`, `containers`, `total_bud_g`, `total_other_g`, `btr`, `packaging_waste`, `avg_bud_thc`, `avg_bio_thc`, `avg_shake_thc`, `untested_bud_g`, `tested_bud_g`, `trim_g`, `other_g`, `harvest_batch_id` (the app batch the row resolved to, law 3 or 4), `landed_at`, `run_id`; the key is (`sheet_hbn`, `metrc_harvest_tag`), so 26007's two rows both land; an unchanged row is counted seen and not rewritten; a changed row is rewritten and counted changed. Grams stay as the sheet holds them (they are the sheet's figures, not the app's ledger); nothing here fabricates a wet weight entry, a lot, a plant tag or a container. `sheet_sync_runs` gains `harvest_rows_seen`, `harvest_rows_landed`, `harvest_rows_changed`, `harvest_rows_skipped` (0074) beside the Labor counts; the Sheet Sync page reads both.
3. THE HISTORICAL LOTS ARE MINTED FROM THE SHEET. For a row whose lot the app does not have (no `harvest_batches` row with that HBN string, and none with the same `harvest_year` and `lot_serial`), the sync mints the harvest batch in the same run: `entry_date` the sheet's Date; `farm_code` the sheet's Farm; `grow_method_code` the grow method whose display name or `hbn_code` matches the sheet's word (Greenhouse GH, Indoor ID, Outdoor OD), checked against the HBN's third segment; `strain_id` the live strain whose name matches the sheet's Strain ignoring case (the sheet is reality; R&D is a strain the app has); `market_strain` the sheet's Market Strain through `inheritMarketStrain` (blank inherits the strain's name, 0.30.9); `manicure` from Manicure?; `metrc_harvest_tag` the row's tag (the first row's when a lot has two); `lot_serial` and `harvest_year` from the seventh segment; `planned_dryspc` the sixth segment (NA blank); `license_value` the farm's grow license as `manualHbn` finds it; `status` open; `born_from` `sheet` (a third `HARVEST_BORN` value; everywhere the app reads `born_from` only `metrc` is excluded, so a sheet-born batch counts as the farm's own harvest in the console, the HBN Queue and the wet weight pick, standing with no lot until its weights come); every row logged under a new `SYSTEM_REASON` `harvest details (sync)`. THE HBN STRING (law 1): before minting, the sync reads METRC's harvest names from the mirror (`metrc_packages.source_harvests`, every token, upper) and reads each through `hbnFromMetrcName`; when a METRC name carries the same year and serial as the sheet row but a different text, the batch is minted with METRC's text as its `hbn`, the sheet's text stays on the row as `sheet_hbn`, and the run's message names the pair. So 26004 mints as `46254-PNN-ID-005-1-NA-26004` with the sheet's 08-24, Apple Fritter, manicure No, tag ...53537; 26007 mints as `46258-PNN-ID-062-0-NA-26007` with Heir Heads, manicure Yes, 08-24, tag ...53530; 26009 mints as the sheet's string with Banana Berry Wine (by name, not by 078). A row refuses (skipped, named in the message, nothing minted) when: the strain name matches no live strain; the seventh segment's year is not the Date's year; the farm or grow method is unknown; the serial is already minted under a different HBN in the app (the collision is his to resolve). The mint never touches `strains`, `grow_methods` or `farms`.
4. THE APP'S OWN BATCHES ARE RECONCILED. For a row whose lot the app has (by string, or by year and serial when the strings differ): the sheet's Market Strain replaces the app's when they differ (a blank sheet cell changes nothing), the sheet's Manicure? replaces the app's when they differ, the sheet's tag fills a blank `metrc_harvest_tag`, and each change is one log row under `harvest details (sync)` with the old value. THE HBN FOLLOWS METRC (his words: "replace our system's HBN with the METRC one"): when METRC's name for the same year and serial differs from the app's string, the app's `hbn` becomes METRC's text, logged under `HBN follows METRC (0.30.203)` with the old string in `old_value`; the sheet's differing string never renames anything (the sheet is not METRC). The report lists every table that stores the HBN TEXT rather than the batch id (pending METRC files, labels, travelers, the mirror's own rows, anything else the grep finds) and for each says whether the rename follows it or why it must not; a rename that would break a pending file refuses in words and names the file. `entry_date`, `farm_code`, `grow_method_code` and `strain_id` of an app-minted batch are never changed by the sync (the app minted them from the same reality at the time; a disagreement there is named in the run's message for the owner, not written).
5. THE ADOPTION FINDS THE HISTORICAL LOTS KNOWN. Nothing changes in `listMetrcAdoptions` or `adoptFromMetrc` except what law 3 and 4 make true: after a run, the mirror's Source Harvest names match the app's batches, the rows read `known`, and `>>` inherits the batch with the sheet's strain and market strain, minting nothing. Brief H's mint from METRC's name (0.30.200) stays for a stranger whose harvest is in neither book.
6. THE SOURCE TODAY IS AN UPLOAD. The Graph pull runs both tabs once the Entra ids are lit (no change to that gate). Until then, Import Data (`/admin/imports`) accepts the workbook itself: a file whose name ends `.xlsm` (a new `IMPORT_KINDS` value with the `XLSB_MAX_BYTES` cap; the ops dash is about 1.5 MB) is read on the spot like the In Testing `.xlsb`, both tabs (Labor as today, Harvest Details as here), recorded as one `sheet_sync_runs` row with trigger `upload`, and the flash reads `Harvest Details: {seen} seen, {landed} landed, {changed} changed, {skipped} skipped; Labor: {seen} seen, {landed} landed.` followed by the run's message when it has one. The bytes are not stored. A `.xlsx` still queues as today.

The smoke's fixture workbook (`/__sheet-fixture`, built with `writeStoreZip`, synthetic rows only) gains a `Harvest Details` tab with the header in row 4 and rows from 7: two historical lots with 46xxx date serials for the smoke's harvest year (one whose name the fixture mirror carries under a different string with the same serial, so the mint takes METRC's text; one whose sheet string is METRC's), one row for a batch the smoke already minted with a market strain the app lacks, one row whose strain the app does not have (skipped and named), one row with a text `Dry Weight` cell.
